# Information design

Choose the representation that makes the required relationship easier to
understand. Use a table for aligned attributes, a chart for meaningful numeric
patterns, and a diagram for mechanisms, boundaries, state, or flow. Use prose
when a sentence is clearer.

Charts need actual data, units, source, and appropriate scales. Label simulated
data. One scale must position marks, ticks, and labels consistently. Avoid
truncated bar baselines that exaggerate change, decorations that imply precision,
and charts without a finding. Use color consistently and provide a readable
table or text equivalent when it carries essential information.

Diagrams should show what crosses a boundary and what changes when an option
changes. Label arrows with useful verbs or data. A box named “system” tells
little. Size the drawing to the decision, leave room for labels, and include a
caption stating its claim. Use `viewBox`, `currentColor`, and meaningful SVG
accessibility names for small inline diagrams.

Dashboards should reveal what needs attention and what action follows. Put
summary before details only when the summary answers a real operating question.
Show freshness when live data can be stale. Never pad a screen with fabricated
gauges, percentages, coordinates, or sparklines to create a technical atmosphere.
